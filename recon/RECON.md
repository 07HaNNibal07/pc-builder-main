## DNS ВЗЯТ (03.09.2026, вторая попытка)
Qrator блокирует headless в любом виде (401/403), но пропускает НАСТОЯЩИЙ видимый Chrome,
управляемый через CDP. Рабочая схема — `cdp_fetch.py`:
  chrome.exe --remote-debugging-port=9222 --remote-allow-origins=* --user-data-dir=C:\Temp\chr-cdp
  → http://127.0.0.1:9222/json → webSocketDebuggerUrl → Page.navigate → Runtime.evaluate
    document.documentElement.outerHTML
Обязателен флаг --remote-allow-origins=* (иначе websocket-хендшейк = 403).
Запуск: WindowsPython312 cdp_fetch.py <url> <выходной_файл> <ожидание_сек>
Требует websocket-client в Windows-Python (установлен).
Результат: 451 КБ, 24 товара с ценами со страницы поиска.
Разметка DNS: название — в `alt="..."` картинки, цена — `product-buy__price...>ЧИСЛО`.
Названия у DNS самые чистые из всех источников (бренд + модель + артикул в скобках)
→ DNS годится как ЭТАЛОННЫЙ справочник для нормализации товаров.

### DNS
- POST `https://www.dns-shop.ru/ajax-state/product-buy/`, form `data={"type":"product-buy","hash":"...","containers":[{"id":"<любое>","data":{"id":"<код>"}}]}`,
  заголовок `X-Requested-With: XMLHttpRequest`. Ответ: `data.states[].data` = `name` (с артикулом в [...]) + `price.current`.
- `hash` обязателен, НЕ привязан к списку (с произвольными кодами работает), но ЖИВЁТ ОГРАНИЧЕННОЕ
  ВРЕМЯ: через ~40 минут тот же hash даёт пустой `states` (уточнено 11.09.2026). На каждой загрузке
  страницы он новый. Адаптер берёт его из HTML: `"type":"product-buy","hash":"..."`.
- В ответе только `name`, `price.current`, `id` (guid), `credit`, `hasHistory` — старой цены нет.
  Наличие — атрибут `data-avail-status` карточки (now / today / tomorrow / later / out_of_stock).
- Листание каталога — `?p=N`, 24 товара на страницу, страницы не пересекаются.
- Меню `restapi.dns-shop.ru/v1/get-menu*` напрямую — 403. Разделы каталога найдены через Chrome,
  лежат в `db/targets.sql`.
- CSRF и cookie НЕ нужны. Контейнеров за запрос — 24 проверено.
- Коды товаров — атрибут `data-code="5621412"` в HTML страницы каталога (24 на страницу).
  В sitemap другие id (шестнадцатеричные `/product/00001c6d3df8d21a/`), к product-buy не подходят.
- `catalog/category/category-filters-new/` — это фильтры и магазины, не выдача.

## Лимит частоты WB в долгом сборе (10–11.09.2026)

Наблюдение за первыми полными прогонами (журнал — `collect_sessions`):

- Первые ~20 минут непрерывного сбора (запрос раз в 8 с) 429 приходят сериями, но
  паузы 20–90 с их снимают: 7 категорий по 300 позиций собраны.
- Дальше лимит ужесточается: 27 отказов из 32 запросов; паузы до 120 с не помогают.
- После 20 и затем 40 минут полного простоя — всё равно 6 отказов из 6.
- Контроль 11.09.2026 01:05: сразу после отказа по SSD запрошена 4-я страница видеокарт
  (видеокарты раньше проходили) — тоже 6 отказов из 6. Значит, ограничивается весь IP,
  а не отдельный запрос. Проверена и отброшена гипотеза о закэшированном 429:
  у отказов `X-Cache-Status: MISS`, другая формулировка запроса тоже получает 429.

Вывод для подсистемы сбора: WB нельзя собирать одним заходом. Нужен планировщик,
который берёт 1–2 категории раз в 1–2 часа, а при серии 429 откладывает площадку на
длительный срок вместо коротких повторов. У DNS за тот же вечер — 92 запроса, 0 отказов.

- Кулер: только «Высота предмета» (см) — отдельного поля высоты кулера нет.
