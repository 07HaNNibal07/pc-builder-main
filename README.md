# Подбор конфигурации ПК

Автоматизированная система поддержки принятия решений при выборе конфигурации
вычислительной техники на основе агрегации данных торговых площадок.

Выпускная квалификационная работа, 09.03.02 «Информационные системы и технологии».

## Устройство

Четыре подсистемы вокруг общей базы данных: сбор, нормализация, подбор,
представление. Сбор отделён от обслуживания пользователя: приложение читает
только накопленную базу и не обращается к площадкам во время запроса.

Готово сейчас: база данных и сбор с Wildberries.

## AI-консультант

`POST /api/ai/chat` — диалоговый слой поверх существующего детерминированного подборщика. Он не заменяет
`collector/advisor.py`: LangGraph хранит контекст по `session_id`, LangChain даёт модели строго описанные tools,
а цены, модели, проверки совместимости и FPS возвращаются только из каталога и функций подборщика.

Доступные tools: `recommend_pc`, `get_build_details`, `find_component_options`, `suggest_upgrade`.
Сессии пока хранятся в памяти через LangGraph `MemorySaver`, поэтому очищаются при перезапуске API.

Скопируйте `.env.example` в `.env` и выберите один провайдер:

```dotenv
AI_PROVIDER=openai
OPENAI_API_KEY=...        # ключ не коммитится
OPENAI_MODEL=gpt-4.1-mini
AI_TEMPERATURE=0
AI_TIMEOUT_SECONDS=60
```

Локальная альтернатива — `AI_PROVIDER=ollama`, `OLLAMA_MODEL=<уже скачанная модель>` и при необходимости
`OLLAMA_BASE_URL`. Контейнер не скачивает Ollama-модели. Если провайдер не настроен, основные API продолжают
работать, а `/api/ai/chat` честно отвечает HTTP 503. Статус конфигурации без секретов доступен в
`GET /api/ai/health`.

После `docker compose up -d --build api` откройте http://localhost:8792/docs и выполните:

```json
POST /api/ai/chat
{
  "message": "Подбери игровой ПК за 120000 рублей для 1440p, желательно AMD",
  "session_id": "demo-user-1"
}
```

В ответе будут `answer`, фактические `builds` подборщика и `tool_calls`. Отправьте следующую реплику с тем же
`session_id`, например «А сколько FPS будет в Cyberpunk?», чтобы использовать контекст диалога.

Qdrant пока является намеренно необязательным расширением (`api/ai/rag.py`): без отдельно развёрнутого Qdrant,
коллекции и embeddings он не участвует в обработке запросов и не может остановить подбор. Его нельзя использовать
как источник текущих цен, моделей, совместимости или FPS — для этого всегда служит каталог.

## База данных

PostgreSQL 16 в Docker, порт `127.0.0.1:5433`.

```bash
docker compose up -d
```

Схема — `db/schema.sql`, применяется при первом запуске контейнера. Основные
таблицы: `models` (изделие производителя), `offers` (изделие на площадке),
`price_snapshots` (цена в момент сбора), `collect_sessions` (журнал сборщика),
`matches` (сопоставление предложения с моделью), `compatibility_rules`
(девять правил совместимости). Справочники: `marketplaces`, `categories`,
`marketplace_categories` (как категория называется на площадке).

## Сбор данных

Сборщик запускается **на стороне Windows**, не из WSL: VPN в WSL даёт
иностранный IP, и российские площадки закрываются. Окружение — `.venv-win`
на Windows-Python 3.12.

```bash
# одна категория, одна страница выдачи (100 позиций)
.venv-win/Scripts/python.exe -m collector.run wb --category gpu --pages 1

# все восемь категорий
.venv-win/Scripts/python.exe -m collector.run wb --pages 3
```

Категории: `cpu`, `mb`, `ram`, `gpu`, `psu`, `case`, `cooler`, `ssd`.

Каждый запрос — сеанс в `collect_sessions`. Предложение создаётся при первой
встрече и обновляется при следующих, цена каждый раз пишется новым срезом —
так копится история цен. Позиции чужих категорий, которые поиск подмешивает в
выдачу, отсеиваются по категории площадки (`subjectId` у WB).

### Wildberries

Публичный поисковый интерфейс витрины `search.wb.ru/.../v9/search`, ключ не нужен.

- Без заголовков браузера (`User-Agent`, `Origin`, `Referer`) — 429 даже на первый запрос.
- Лимит частоты срабатывает «приступами». Сборщик делает запрос не чаще раза
  в 8 с, а на 429 ждёт 20, 40, 60, 90, 120 с. Страница из 100 позиций
  занимает от 8 с до пары минут.
- Цены приходят в копейках; артикул производителя часто стоит в скобках в
  конце наименования — это ключ сопоставления на этапе нормализации.

### DNS

Защита DNS пропускает к каталогу только настоящий браузер, поэтому раздел
каталога открывается в Chrome, управляемом по протоколу CDP (`collector/browser.py`).
Во время сбора окно Chrome видно на экране — закрывать его нельзя.

- Со страницы каталога берутся коды товаров (`data-code`, 24 на страницу) и
  ключ запроса цен (`hash`).
- Цены и наименования по кодам запрашиваются напрямую, без браузера:
  POST `/ajax-state/product-buy/`.
- Ключ живёт ограниченное время, поэтому берётся заново с каждой страницы.

```bash
.venv-win/Scripts/python.exe -m collector.run dns --category cpu --pages 5
```

### Ozon

Прямой запрос к внутреннему интерфейсу получает 403 даже с cookie браузера.
Тот же запрос через `fetch()` изнутри открытой вкладки ozon.ru проходит,
поэтому адаптер держит Chrome с сайтом и выполняет запросы в нём.
Выдача — порциями по 8 товаров; адрес следующей порции с одноразовым токеном
лежит в виджете `infiniteVirtualPaginator`, страницы проходятся по цепочке.
«Цена до скидки» у Ozon часто завышена и для сравнения не годится.

### AliExpress

Chrome открывается ненадолго — за cookie, дальше прямые POST-запросы к
`/aer-webapi/v1/search`, листание параметром `page`. Параметр `catId` выдачу
не фильтрует, а номер категории в карточке ставится как попало: процессоры
Ryzen приходят под четырьмя разными номерами, один из которых общий с
мини-ПК. Поэтому у AliExpress, в отличие от остальных площадок, чужие товары
отсеиваются по названию — правила `TITLE_RULES` в `collector/adapters/ali.py`.
Номер товара берётся из данных трекинга: часть адресов имеет вид
`/item/1_772684063.html`. Доставка оплачивается отдельно и хранится в `raw`.
После ~40 запросов за короткое время площадка показывает капчу и отдаёт
пустую выдачу; если пройти капчу в окне Chrome, сбор можно продолжать.

### Яндекс Маркет

Отдельного интерфейса нет: страница поиска разбирается в Chrome по разметке.
У каждой карточки атрибут `data-zone-data` с JSON — модель Маркета (`modelId`),
категория (`hid`), магазин и цены. На витрине крупно показана цена с картой
Яндекс Банка; для сравнения берётся цена со скидкой для всех покупателей.

## Задания сбора

Что собирать, задаёт таблица `collect_targets` (`db/targets.sql`): для каждой
площадки и категории — поисковая фраза (WB) или путь раздела каталога (DNS).
Новая категория добавляется строкой в таблице, без изменения кода.

## Просмотр базы

Adminer: http://localhost:8791 — сервер `db`, пользователь `pcb`, пароль `pcb`,
база `pcb`. Представления с русскими колонками: `v_offers` (предложения с
последней ценой), `v_categories` (сводка), `v_sessions` (журнал сбора).

## Резервная копия

Данные живут в томе Docker `pcb-data`, в репозиторий не входят. Копия —
сжатый дамп в `data/` (папка исключена из git):

```bash
docker exec pcb-db pg_dump -U pcb -d pcb | gzip -9 > data/pcb-$(date +%Y%m%d-%H%M).sql.gz
# восстановление в пустую базу
zcat data/pcb-YYYYMMDD-HHMM.sql.gz | docker exec -i pcb-db psql -U pcb -d pcb
```

## Прототип 3D-сборки

`web/prototype-3d/index.html` — сборка ПК в 3D на Three.js, открывается прямо
из файла. Корпус, плата, видеокарта и кулер строятся кодом по размерам из
характеристик (параметрические шаблоны), поэтому правила совместимости видны
наглядно: слишком длинная видеокарта упирается в передние вентиляторы,
высокий кулер выходит за стекло, несовместимая деталь подсвечивается красным.
Сборку можно задать адресом: `index.html?case=itx&gpu=g5090&cooler=dual`
(ещё `mb`, `glass=0`, `gpu_out=1`). Пока размеры справочные, не из базы.
